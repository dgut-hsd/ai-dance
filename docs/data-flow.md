# 数据流总览（帧格式 / 参考序列 / 实时帧 / 谱面 / 节拍）

> 阅读对象：模块 C 及需要理解"评分引擎与参考、实时数据的对接方式"的人。
> 依据：`docs/interface-contract.md`。本文件只描述数据流，不重复各 schema 的字段细节
> （字段细节见契约 §3/§4/§5 与 `docs/chart-events-spec.md`）。

## 1. 一句话总览

一份通用的**帧格式（§3）**被三种用途复用：离线的**参考序列文件（§4）**、实时的**玩家帧消息（§5）**；
评分 = **姿态比对（参考对实时，帧级连续相似度 = 基底分）** + **时机比对（谱面音符 + 判定窗 = 节奏 bonus + 连击）**，
其中时机基准是**音频时钟 + chart**，与参考序列文件正交。

## 2. 四种元素与两个角色

| 元素 | 位置 | 产生者 | 消费方式 |
|---|---|---|---|
| 帧格式 | 契约 §3（类型定义） | ——（共用的 schema） | 四处复用，非数据文件 |
| 参考序列文件 | 契约 §4 `reference/<danceId>.json` | 离线端 | 教练顺播 + 逐帧比对；**运行时只读** |
| 实时帧消息 | 契约 §5 | 实时端（你） | 摄像头每帧产出，**即用即弃不落盘** |
| 谱面 chart | 契约 §4.2（内嵌 `seq.chart`） | 离线端/人工 | 判定"何时判、判哪帧、判哪些骨、达线标准" |
| 节拍 timing | 契约 §4.1（`meta.timing`） | 离线端 | 供谱面铺拍 / HUD 对拍 / 未来 bars 模式；目前引擎为旁路 |

## 3. 帧格式（§3）：唯一"形状"，多种用法

帧格式是**类型（schema）**，不是数据文件。它声明任何一帧都必须长这样：

```jsonc
{
  "t": 0.066,                // 相对起点秒数
  "bones": [[0,0.92,0.38], /* 9~10 组单位向量 */],
  "rootYaw": 0.12,           // 躯干偏航（用于对齐；精确定义[待定]）
  "rootVel": [0.1,0,-0.05],  // [可选] 根运动速度（可视化用）
  "grounded": true,          // [可选] 只回退运动学
  "rootPos": [0,0,0],        // [可选] 髋中点为原点可省略
  "conf": [0.95, ...]        // [可选] 每骨骼置信度，缺省全 1
}
```

**评分只消费 `bones` / `conf`**；`rootVel`/`rootPos`/`grounded`/`rootYaw` 仅供可视化，不进相似度。

### 三种用途共享同一形状 → 打分逻辑只写一份

```
§3 帧格式（类型）
  ├── 参考文件 frames[]  ← 标准答案（离线、静态、量大、可省略 conf）
  └── 实时帧消息         ← 玩家观测（瞬时流、始终带 conf、外加信封 _src/_seq）
```

## 4. 参考序列文件（§4）：标准答案 + 教练舞源

- 结构：`schema / danceId / meta{bones,frames} / bones / frames[]`
- 不变量：`numFrames = fps × durationSec`；任意两帧 bones 不同（§7 验收）。
- 两类用途：
  1. **教练角色**：跟跳模式左侧 3D 小人按 `songTime` 逐帧读 `frames[]` 顺播。
  2. **判定基准**：同一时刻的参考帧与玩家帧送入 `poseScore` 比相似度。

## 5. 实时帧消息（§5）：玩家观测流

= **§3 帧 + 信封**：

```jsonc
{ "t": 12.345, "bones": [...], "rootYaw": 0.12, "conf": [...],
  "_src": "live", "_seq": 741 }
```

- `_seq` 单调递增 → 丢帧/乱序诊断；`_src` 固定标记实时来源。
- 与参考文件的差异：**带 envelope、不落盘、时刻是真实观测时间**。
- 发布建议：页面内函数调用/`postMessage`，v1 不引 WebSocket。

## 6. 谱面 chart（§4.2）与节拍 timing（§4.1）：音乐时间的两把尺子

### chart：事件层（轻量指针，不复制姿态）

音符**不带 bones**，用 `refFrameIdx` 指向参考文件的某帧作为目标姿态：

```jsonc
{ "t": 2.500, "type": "pose", "refFrameIdx": 120, "bones": [2,3], "threshold": 0.7 }
```

- `refFrameIdx` → "判哪一帧"（缺省 `round(t*fps)`）；`bones` → "判哪些骨"；`threshold` → 达线标准。
- 姿态数据仍在参考文件，chart 只引用索引 —— **音符判定 = chart + 参考文件 + 玩家帧 三方协同**。
- 权威位置 = 参考文件内嵌 `seq.chart`；独立 `reference/<danceId>.chart.json` 仅作编辑器交换格式（`{schema:"chart/v2", sequenceFile,...}`），导出时合并回内嵌。

### timing：节拍栅格（时间维坐标系）

- 表达 BPM/变速/拍号/弱起一次算好写入；运行时只读不重算。
- 用途：**谱面铺拍**（音符 `t` 从拍栅格产生）、HUD 对拍、未来按小节事件（bars）。
- 见效证据：组长 demo `chart.json` 音符间隔 ~2.0s = 120BPM × 4/4 一小节。
- **当前评分为旁路**：判定时机用音符自带 `t`，暂不消费 timing/v1。

## 7. 判定机制：两条正交的分数叠加

```
               ┌─ 参考帧（同一时刻顺播）──┐
玩家实时帧 ────┼───────────────────────┼─→ poseScore(bones+conf) = 姿态标不标准 = 基底分
               └─ chart 音符 t + timingWindows(±50/100/150ms) ──→ hitΔt 命中档位 = 时机对不对 = bonus+连击
```

| 维度 | 数据源 | 产出 |
|---|---|---|
| 标不标准 | 玩家帧 vs 参考帧（帧级相似度） | 连续基底分（S/A/B/C/D 等级基于平均 pose） |
| 踩点准不准 | chart 音符时刻 + `judgeTime = t + offset + judgeOffsetSec`，取玩家最近帧 | PERFECT/GREAT/GOOD/MISS + combo |

总分 = 基底分 × (1 + combo 加成) + 节奏 bonus；两者正交。

## 8. 引擎当前实际消费表（现状备份）

| 数据 | 是否被引擎消费 | 说明 |
|---|---|---|
| `seq.frames[]`（参考） | ✅ | 教练播放 + poseScore 比对基准 |
| 实时帧（§5 信封） | ✅ | `bones`/`conf` 进入评分；`_seq` 未用（离线回放无流） |
| `seq.meta`（fps/boneCount/danceType） | ✅ | 兼容校验用 |
| `seq.chart`（内嵌，权威位置） | ✅ | 事件解析 + timingWindows + boneWeights（扩展待确认） |
| `meta.timing`（§4.1） | ⬜ 旁路 | bars 模式（待办）与跨端需求出现时接入 |
| `rootVel/rootPos/grounded` | ❌ | 可视化用，不进相似度 |
