# web_dance/ — DANCE ARENA(three.js 网页版舞蹈系统)

把 `pose_capture/` 的舞蹈动捕管线(摄像头 → MediaPipe → 契约帧)搬进网页,
用 **Three.js** 驱动 **FBX / GLB 人形模型**,并套上一个**游戏化**的舞台界面。

> 与 `backend_process` / `frontend_dis` 完全无关,不依赖 Python。
> 直接复用 `pose_capture/` 的 `contract / mocap / export / playback / pose-engine`。

## 快速运行

```bash
# 在仓库根目录
npm install
npm start
# 浏览器打开 http://localhost:8000/web_dance/ (选歌主页)
# 或直接进游戏页 http://localhost:8000/web_dance/dance.html
```

谱面编辑器(`chart-editor.html`)的「保存到歌单」需要写 `songs/` 与更新 `index.json`,
必须由 Node 服务提供(`server/index.js`,`npm start`),`python -m http.server` 只读不能保存。
编辑器流程:上传「舞曲文件夹」(内含 fbx + 音频) → 在时间轴打判定点 → 保存到歌单
(自动生成 `songs/<danceId>/` 目录、`<danceId>.json` + `<danceId>.chart.json`,并在 `songs/index.json` 追加该曲)。
真人 PK 高光录制、剪辑和扫码领取需要此 Node 后台。Python 静态服务器只能运行游戏，不能处理视频。默认本地存储无需云凭证；手机访问与阿里云配置见 [高光功能说明](../docs/highlights-v1.md)。

选歌主页 → 游戏页的跳转参数:`?mode=challenge&dance=hiphop&song=pop-demo&autoload=1`
(`mode` 三选一,`dance`/`song` 为库内 id,`autoload=1` 自动加载默认舞者)。

- 必须走 http(localhost 即可),`file://` 打不开 ES module 且拿不到摄像头。
- 模型 / three.js / MediaPipe wasm 都从 CDN 加载,需要联网。

## 使用

1. 点「使用默认舞者」加载 three.js 官方示例(Michelle,Mixamo 骨架);或点「加载本地 FBX / GLB」
   用自己的模型(也支持 ReadyPlayerMe,把 `.glb` 文件或 URL 填进去即可)。
   (本地建议用 `.glb` / `.fbx`;`.gltf` 若含外部 bin/贴图,本地 objectURL 加载可能失败。)
2. **自由模式**:点「开始」,3D 舞者实时镜像你的动作。
3. **跟跳挑战**:点「跟跳挑战」→「开始」,舞台上会出现**两位舞者**——左侧是跳参考舞的
   3D 教练(由 `dance-sequence/v1` JSON 逐帧驱动),右侧是你(实时动捕);先 3-2-1-GO 倒计时,
   跟着教练跳,右下角实时计分(分数 / 连击 / 匹配度 / 评级)。底部「舞蹈」「歌曲」下拉可切换
   舞曲:内置「合成示例舞」+ `songs/<danceId>/` 里的 Mixamo 动作(Hip Hop / Salsa,已转成挑战序列,
   短片段循环到 24s);也可「加载参考 JSON」(即 `pose_capture` 导出的文件)。
4. **舞者表演**:底部「动画」下拉可切换舞蹈。默认列出**内置舞曲**(`songs/<danceId>/<danceId>.fbx`
   里的 Mixamo 动作,如 hiphop / salsa),加上模型**内嵌的 FBX/GLB 动画**
   (默认 Michelle 自带桑巴舞 SambaDance)。内置舞曲做**世界空间重定向**(先按骨骼名匹配,
   再用源/目标骨架的休息姿态差对齐朝向,避免 Mixamo FBX 与 glTF 骨架的 90° 朝向错位),
   只保留旋转轨道(原地跳),短片段自动循环播放。想加新舞:把 FBX 放进 `songs/<danceId>/<danceId>.fbx`,
   在 `dance-library.js` 的 `BUILTIN_DANCES` 里补一行。
   **音乐**:每支舞放歌单里它自己的曲子(`songs/index.json` 中该舞 `defaultSongId` 的音频),
   歌单里查不到的(如模型内嵌动画)才退回默认循环伴奏。动作比曲子短很多(salsa 2.25s / 曲子 24s)
   → 动作与音乐都循环;动作和曲子差不多长(copydance1 28.7s / 曲子 30s)→ 各放一遍,放完即停
   (否则每循环一次动作和音乐就错开一点)。
5. **选曲页试听**:PK 选曲(卡片轮播 / 试跳)时,选中哪张卡就试听这支舞自己的音乐;
   点「开始挑战」会自动停掉试听,音乐交给挑战会话放同一首。
6. 快捷键:`空格` 开始/停止,`M` 切换左右镜像。

## 原理(把「契约帧」搬到 3D 骨架)

`pose_capture` 产出的契约帧只有**骨骼单位向量**(+ `conf`),不含绝对位置。`retarget.js`
先用 `reconstructJoints` 把单位向量重建成目标关节点(髋为原点),再套到任意人形骨架
(Mixamo / ReadyPlayerMe 命名):

1. 加载时测出模型的 `right/up/forward` 休息基(前方用脚趾方向校正)与各骨长度。
2. **四肢**用位置级**两骨 IK**(`ik.js`):末端(腕/踝)精确到位,肘/膝用 pole 朝正确方向弯折。
3. **脊柱**方向对齐,`setFromUnitVectors(restDir, targetDir)` 求增量四元数转回局部空间。
4. **头**用相对中性朝向的偏差;**根运动**水平位移由 `rootVel` 积分、垂直在贴地时用脚踝
   反推髋高(蹲下)、腾空时用速度积分(跳跃);脚掌做简单 foot-IK。

### 重定向基准:载入时对齐到 T-pose

重定向做的是「把源骨**相对其休息姿态**的旋转搬到目标骨」,所以两边必须先对「中立姿态」有共识。
源 FBX(Rokoko/Mixamo)是 T-pose,而 dancer_girl 原本的休息姿态是「手臂垂在身侧 + 一条腿在前」
(`avatar.js` 拿模型自带动画第 0 帧当中立),两者每根骨差 57~131° —— 这个固定补偿会把关节转动轴
一起拧过去:方向误差 37.9°、手插进躯干 45 帧、明显"不像"。

现在 `avatar.js` 的 `applyRetargetTPose()` 在载入时把模型的休息姿态**对齐到参考骨架的朝向**
(方向 + roll,参考姿态由 `tools/retarget-tpose.mjs` 从 `songs/hiphop/hiphop.fbx` 烘到
`web_dance/retarget-tpose.js`)。实测:方向误差 37.9°→4.4°,手插进躯干 45→13 帧。

- 关掉对比:URL 加 `?tpose=off`。
- 代价:模型静止(idle / 停止后)会以 T-pose 站立。
- 换参考骨架:`node tools/retarget-tpose.mjs --src <fbx>`,再刷新页面。

### 表演路径:碰撞避免 + 髋部竖直位移

`dance-library.retargetClipToSkeleton()` 是「直接搬源骨世界朝向」,原本有两处不如教练路径:

1. **没有碰撞避免** → 源里本来就贴着身体的手(抱臂/手贴肚子)在目标模型的比例下会穿进躯干。
   现在逐帧跑一遍 `skeleton-collision.js`(与教练 `retarget.js._resolveCollisions()` 同一套
   胶囊分离逻辑,独立实现)。实测手进躯干帧:**13 → 0**,方向误差只从 4.4° 涨到 4.6°,
   重定向耗时 190ms → 331ms(每次载入一次性成本)。可用 `{ collision: false }` 关掉。
2. **不消费位移** → 髋高恒为休息值,蹲下/起跳会浮空、走位完全不体现(脚底摆幅 0.32 单位)。
   现在把「源髋相对其休息位置的三维偏移」换到源髋静止坐标系、按身高比缩放、再映射到目标髋静止朝向,
   写成髋部位置轨道;并加一层**脚底单向贴地**(插进地板才抬,不压低正常抬脚)。
   实测:脚底摆幅 **0.32 → 0.00**、穿地帧 6 → 0、髋高 0.86~1.19。
3. **走位要「去漂移」再限幅**(`web_dance/root-travel.js`):源录像的髋部水平位移含两种成分 ——
   编舞真的左右移动(快)与整支舞的缓慢漂移(慢)。直接照搬会把舞者带出舞台
   (copydance1 的 Z 摆幅 **2.96 单位** > 地台半径 2.88)。现在用 τ=2.5s 的移动平均去掉低频成分、
   再按 **2.2 单位** 兜底限幅:水平最大 **2.96 → 0.65 单位**(离中心最远 1.52 → 0.53),
   快的左右移动原样保留,慢漂移被摊到几秒里慢慢拉回中心(硬夹会在极值处"卡住",滑移看得见)。
   `{ rootMotion: false }` 可整体关掉。

教练路径(`retarget.js` / `ik.js`)另有三处修复:

1. **末端目标改成「相对骨骼原点的偏移」**而不是「重建关节的绝对位置」—— 重建肩点与模型实际骨骼
   原点平均差 0.139 单位(≈臂长的 29%,来源是锁骨偏移),会让腕部目标超出臂长、把手臂拉直
   (**肘弯角误差 30.7° → 0.5°**)。
2. **pole(肘/膝弯折方向锚点)必须与末端目标同口径** —— 之前 pole 用的是重建肘/膝的**绝对**位置,
   与相对口径的末端目标错开同一个位移,**弯折平面被转掉**:实测肘平面法向误差 18°(是方向误差的
   1.7 倍)。统一口径后:平面误差 **18° → 2–3°**、上臂方向 **11° → 1–2°**。
3. **`ik.js` 的镜像解只在 pole 给不出方向时才用 hint 选边** —— 之前无条件按上一帧中间关节选边,
   源动作快速摆到另一侧时会把关节锁在**反侧**并持续数帧(实测:前踢腿被摆到身后,**100°**,
   连续 4+ 帧)。现在:大腿/小腿误差 **1.9° → 0.1°**、最大 **100° → 9°**,帧间抖动不变。

### 脊柱:配置因子要按骨长归一化

`SPINE_TARGETS` 的因子(0.6/0.8/0.95)是「每段相对竖直的插值量」,而「髋→肩」的合成方向是各段的
**长度加权平均** ≈ 0.79 —— 整条脊柱的净弯折只有源的 ~79%(实测脊柱方向误差 5.2°)。现在按
加权平均归一到 1(S 曲线形状不变):最上段骨误差 **1.0°**、髋→Spine2 合成 5.2° → 3.2°。
剩下的 3.2° 里 1.2° 是锁骨/肩点(契约没有锁骨骨),其余来自「髋→Spine」这段——
它的长度 0.098 几乎等于脊柱骨长,方向只受**骨盆**控制,而 v2 只带 `rootYaw`(偏航)没有骨盆倾斜。

### 肩部 ROM 锥:内收上限 40° → 60°

`clampArmDirection` 作用在「肩→腕」向量上。原内收上限 40°(侧向分量 −0.643)对 copydance1 太紧:
这支舞有「手跨到对侧身体」的段落(侧向分量到 −0.93 ≈ 68° 内收),被钳住后方向被拧掉 20–42°,
表现为**上臂误差最大 33°、6.6% 的帧触发**。放宽到 60°(碰撞层照常开):

| 指标 | 40° | 60° |
|---|---|---|
| 教练上臂均值 / 最大 | 1.55° / **33°** | **1.04° / 18°** |
| 前臂最大 | 43–57° | 13–27° |
| 帧间抖动(手臂,源 5.38°) | 5.44°(最大 40.6°) | **5.38°(最大 22.8°,与源一致)** |
| 手进躯干帧 | 0 | **0** |

注意**别完全放开**:180°(等于不钳)实测反而恶化到均值 8.2°/最大 62° —— 锥约束本身在帮 IK 选解。

### 手臂/手「陷进身体」:碰撞代理半径 vs 衣服厚度

先回答一个常见误解:**这不是布料物理问题** —— 角色是刚性蒙皮网格,项目里没有布料解算(加布料也不会
管手臂的姿势)。真正的原因是**碰撞代理(胶囊)的半径比蒙皮后的实际表面小得多**:

| 部位 | 代理半径(旧公式) | 网格实测(骨中段管道 P50) | 倍数 |
|---|---|---|---|
| 上臂(含袖子) | 0.031 | 0.145 | 4.7× |
| 前臂 | 0.031 | 0.098 | 3.2× |
| 胸腔 | 0.089 | 0.19 | 2.1× |
| 头(含发) | 0.031 | 0.226 | 7.4× |

所以"骨架不重叠"但袖子照样压进外套。但**直接按实测半径强制表面分离不可行**:目标的衣服比源表演者
的身体厚得多,源里正常的贴身姿势在目标上就是压进去 —— 全推会把手臂推歪。实测(对源真值的手臂方向误差):

| 半径设置 | 上臂误差(均值/最大) | 9 骨平均 |
|---|---|---|
| 旧公式(完全不放大) | 0.6° / 7° | 4.3° |
| 混合 0.25 | 0.9° / 16° | 4.4° |
| 混合 0.5 | 2.3° / 23° | 5.5° |
| **网格实测(全量)** | **27.1° / 68°** | **27.5°** ❌ |

现在的策略(实测折中):
- **手单独成段**:之前手臂只到腕(肘→腕),手掌根本不在碰撞胶囊里 → 手深陷胸腔时只有前臂在挡。
  现在补了「腕→指尖」一段,写回时只转手骨、不拽前臂。
- **深度阈值(allowance)**:只压超过阈值的深层穿插,放过"衣服互相贴住"的正常接触 —— 全量强制分离
  会把手臂推歪(见上表),阈值是关键。当前默认 `collisionAllowance=0.05`(5cm)、`radiiBlend=0.35`。
- **外科式半径**:上臂/大腿/头保持旧的小半径(近端天生在躯干里,放大会永久外张),只放大前臂+手。
- **`?collisionradii=mesh|old`** 可两边一起强制;`--radii=` / `--allowance=` 见 `tools/audit-retarget.mjs`。

**但要说实话**:胶囊碰撞有个天花板 —— 源动作里"手绕到胸前、指尖往后勾"的姿势,把手指放到离脊柱轴
~2cm 处,而躯干被建模成一根竖线胶囊,最近点在**侧面**,所以手被往侧向推而不是往前推,最深 ~11cm 的
穿模压不下去。要彻底解决只能二选一:**①把袖子/外套调薄(建模,最直接)**或 **②把躯干换成体积
(椭球/网格)碰撞**。详见 `docs/roadmap.md`。

### 改完怎么验

`node tools/audit-retarget.mjs` —— 对源 FBX 真值体检 10 根契约骨的方向/弯折角/穿模/根运动,
两套基准对比。(注意「head」那一行是契约口径、方向由脖子决定,不进总平均。)

### 教练路径也消费根运动 + 骨盆倾斜

序列新增两个可选字段(向后兼容,浏览器按字段是否存在消费):

- **`rootPos`** 根位移(相对 bind 位置、按源髋高归一化)→ 教练跟着参考走位。
  实测髋部 X/Z 摆幅 **1.08 / 3.19 单位**,与序列理论值 1.10 / 3.22 一致;旧序列没有该字段时
  自动回退到原来的「固定站位 + 脚贴地运动学」。
- **`pelvisPitch` / `pelvisRoll`** 骨盆前倾/侧倾(相对 bind 的增量)→ 修「只做偏航」时
  「髋→Spine」这段固定偏移的方向(实测该段误差 8.6°)。符号用「骨盆朝向误差的**波动**」标定:
  pitch 取负、roll 取正时波动 **4.05°→2.20°**(倾斜跟上了源),脊柱方向误差 5.1°→4.8°。
  用均值看不出来 —— 那 8° 是「通用参考 vs 这支舞」的骨盆常数差,只能靠每支舞对齐消。

### 每支舞用自己的源当基准(表演路径)

载入一支舞时,`main.js` 会调 `avatar.realignRetargeter()`:用**这支舞自己的源骨架**的休息姿态
重新对齐模型基准并重建 `Retargeter`(而不是只用烘好的通用 Mixamo 参考)。实测 10 骨方向误差
**4.6° → 2.1°**、大腿/小腿 **11° → 1.5°**、膝弯角误差 0.1°。教练路径不受影响(实测没有收益,
仍用通用参考)。

### 缓存源骨架必须还原 bind 姿态

`loadDanceClips()` 缓存解析好的源骨架,而重定向会在源骨架上播动画 —— 所以
`retargetClipToSkeleton()` 现在每次先把源骨架还原到 bind 姿态(`restoreBindPose`)。
不还原的话,**切走再切回同一支舞时,读到的「休息姿态」其实是上一段动画的最后一帧**,
基准就错了。回归:同一个缓存源连续重定向两次,与全新解析的结果逐位一致。

## 已知取舍 / 后续

- **四肢两骨 IK(位置级)**:腕/踝精确到位,肘/膝朝正确方向弯折;髋部横向(hip joint)
  因骨架无独立髋骨,有厘米级近似。手腕/脚踝的绕轴 roll 仍是最小扭转解。
- **根运动(方案 C)**:契约帧已带 `rootVel`(髋中点速度)+ `grounded`(贴地标志),
  `retarget.js` 积分出水平位移并还原跳跃;`grounded` 抑制积分漂移,评分仍只比 `bones`(平移不变)。
- **手势舞的手指**未做 retarget(身体会动,手指不逐节驱动);手势舞模式主要还原上半身。
- MediaPipe 跑在主线程(与 `pose_capture` 一致),可后续用 Vite 打包丢进 Web Worker。
- 朝向/镜像若有偏差,用底部控制条里的「镜像」/「朝向」按钮一键切换
  (对应 `main.js` 的 `state.mirror` / `state.flipFacing`)。

## 动效实验台(ui-lab/)

`ui-lab/` 是独立于主页面之外的「动效实验台」:复用主页面的三渲二舞池作背景,
把一次「命中判定」做成一份**多轨动效谱**(判定文字 / 冲击波环 / 定向火花 / 震屏 / hit-stop / 闪光 / 暗角 / 里程碑),
一个 **Juice 总控**(0=扁平,10=全开)+ 每轨倍率微调,调好后点「复制配方」把参数回填到 `main.js`。

- 打开 `http://localhost:8000/web_dance/ui-lab/`
- 按 `P` / `G` / `M` 触发 PERFECT / GREAT / MISS,空格开自动连打看连击热度与里程碑。
- 核心原语在 `tween.js`(统一 rAF 时钟 + 缓动/弹簧 + hit-stop)和 `juice.js`(震屏/闪光/暗角/冲击波/定向火花),
  这两份文件设计为可直接搬回主页面复用。
